Senmei implementation guide

Build subtitles from the screen back to the file.

Do not start with Block headers. Start with the viewer: the selected dialogue appears over the final picture at the right movie time, overlapping cues survive, and old text cannot leak across a seek or file change. Then work downward until the design finally asks for bytes.

Scope

Senmei currently recognizes S_TEXT/ASS. This guide builds a safe plain-text renderer while preserving enough ASS metadata to replace it with a full renderer later. WebCodecs is not involved: ASS packets are text, not compressed audio or video.

Zoom level 0 · Product behavior

1. First define what “subtitles work” means

A complete first milestone has observable behavior, not merely parsed strings:

  1. The user can choose a subtitle track or turn subtitles off.
  2. Text appears and disappears according to the same media clock as the movie.
  3. Every cue active at that instant is rendered; one cue does not hide another.
  4. The overlay follows the displayed picture through resize and fullscreen.
  5. Subtitle failure does not stop audio or video.
  6. Stop, seek, track switch, and new playback immediately invalidate old cues.

This tells us what the system needs: track selection, a shared clock, timed cues, a visual plane, bounded read-ahead, and a session lifecycle. None of that belongs in an EBML VINT helper.

The central distinction

Packet arrival time is not display time. A cue may be read thirty seconds early or half a second late; only its media interval decides whether it belongs on screen.

Zoom level 1 · System

2. Give every layer one job

MKV demuxerYields selected-track bytes with start and end times.
ASS interpreterTurns packet fields into a renderable cue.
TimelineBuffers future cues and selects all active cues.
RendererPlaces safe text above the final picture.

The player sits above those layers and supplies the clock and lifecycle:

Player session
├── shared media clock ───────────────┐
├── video renderer                    │
├── audio scheduler                   │
└── subtitle controller               │
    ├── producer: MKV → ASS → cues    │
    └── update(nowUs): timeline → DOM ◀┘
Boundary rule

The MKV reader does not touch the DOM. The ASS interpreter does not invent timing. The renderer does not know about Clusters. The subtitle controller does not create a second playback clock.

Zoom level 2 · Control flow

3. Make the controller small enough to understand

The player's desired interface is more useful than a giant implementation:

type SubtitleController = {
  update(nowUs: number): void;
  seek(targetUs: number): Promise<void>;
  select(trackIndex: number | null): Promise<void>;
  stop(): void;
};

const subtitles = createSubtitleController(mkv, overlay, reportError);
await subtitles.select(defaultTrackIndex);

// The existing player tick owns time:
subtitles.update(playerClock.nowUs());

select() starts an asynchronous producer for one track. It returns after the session is ready, not after the entire subtitle stream has been read. update() is synchronous and never waits for file or network I/O. stop() clears the overlay immediately and invalidates pending work.

Producer and consumer run at different rates

Producer

Reads packets, interprets ASS, and fills a bounded future-cue buffer.

Consumer

Receives current media time, expires old cues, and renders active ones.

Bound read-ahead by media horizon as well as cue count. One hundred dialogue cues can cover minutes, while one hundred karaoke fragments may cover seconds. A target such as “read until at least 30 seconds beyond nowUs” describes the actual resource policy.

Do not bolt on a second animation loop

Video, audio, and subtitles need one media timeline. A separate subtitle requestAnimationFrame with its own start time creates drift and makes pause or seek coordination harder.

Zoom level 3 · Visual output

4. Render all cues active at the current time

Use half-open intervals: a cue is active at startUs ≤ nowUs < endUs.

function update(nowUs: number) {
  cues = cues.filter((cue) => cue.endUs > nowUs);

  const active = cues
    .filter((cue) => cue.startUs <= nowUs)
    .sort((a, b) => a.layer - b.layer || a.readOrder - b.readOrder);

  renderer.render(active);
}

The first filter removes only expired cues; future cues remain buffered. Selecting all matching cues preserves overlapping dialogue, signs, and multi-speaker events. An exclusive end prevents the old cue lingering when another begins at exactly its end.

Place one overlay above the composed player

In Senmei, the split comparison is one visual composition. Put the subtitle layer inside the positioned #comparison wrapper, after both viewports, rather than inside either clipped half: 

<div id="comparison">
  <div id="originalViewport">…</div>
  <div id="upscaledViewport">…</div>
  <div id="subtitleOverlay" aria-live="off"></div>
</div>
#comparison { position: relative; }

#subtitleOverlay {
  position: absolute;
  z-index: 4;
  inset: auto 5% 5%;
  color: white;
  text-align: center;
  white-space: pre-wrap;
  pointer-events: none;
  text-shadow: -1px -1px 1px black, 1px 1px 1px black, 0 2px 4px black;
}

Set textContent, never innerHTML. Subtitle bytes are untrusted media, not page markup. Update the DOM only when the active cue set changes.

Rendering invariant

The overlay covers the displayed picture once, remains outside the Anime4K texture pipeline so glyphs stay crisp, and is included in the element entered into fullscreen.

Zoom level 3 · Timeline contract

5. Keep timing and presentation metadata together

The timeline should receive a complete cue, not raw text:

type SubtitleCue = {
  startUs: number;
  endUs: number;
  readOrder: number;
  layer: number;
  style: string;
  text: string;
  raw: string;
};

A plain-text renderer may use only text, timing, layer, and read order today. Keeping style and raw event data prevents this temporary renderer from becoming the permanent data model.

Use the player's clock

requestAnimationFrame tells the player when it can paint; it does not tell the player what movie time it is. Ask a shared player clock for nowUs. During pause, that value freezes. On seek, it jumps. If audio becomes master, map the AudioContext clock to media time once and let video and subtitles use that mapping. 

function playerTick() {
  const nowUs = playerClock.nowUs();
  subtitles.update(nowUs);
  video.renderDueFrame(nowUs);
  requestAnimationFrame(playerTick);
}

Run subtitle expiry even when the video queue is temporarily empty. Otherwise stale text can remain forever during a video stall.

Zoom level 4 · Format interpretation

6. Interpret an ASS event without confusing it with a file line

In a standalone .ass file, a Dialogue: line contains start and end fields. Matroska stores timing in the Block, so an embedded ASS event has nine fields: 

ReadOrder,Layer,Style,Name,MarginL,MarginR,MarginV,Effect,Text
12,0,Default,,0,0,0,,Hello, Emilia!\N{\i1}Are you okay?

Text may contain commas. Split at the first eight commas and preserve the entire remainder as field 9: 

function splitAssEvent(event: string): string[] {
  const fields: string[] = [];
  let start = 0;

  for (let i = 0; i < 8; i++) {
    const comma = event.indexOf(",", start);
    if (comma === -1) throw new Error("ASS event has fewer than 9 fields");
    fields.push(event.slice(start, comma));
    start = comma + 1;
  }

  fields.push(event.slice(start));
  return fields;
}

Be explicit about plain-text loss

  • \N becomes a forced newline.
  • \n can become a space for the first version.
  • \h becomes a nonbreaking space.
  • Override tags such as {\i1} can be stripped, knowingly losing styling.
  • Events that enable drawing mode with \p1 or above are not text; skip them. 
function packetToCue(packet: SubtitlePacket): SubtitleCue | null {
  const raw = new TextDecoder("utf-8", { fatal: true }).decode(packet.data);
  const fields = splitAssEvent(raw);
  const text = toPlainAssText(fields[8]!);
  if (text === null || text === "") return null;

  return {
    startUs: packet.startUs,
    endUs: packet.endUs,
    readOrder: parseInteger(fields[0]!),
    layer: parseInteger(fields[1]!),
    style: fields[2]!,
    text,
    raw,
  };
}

Use fatal UTF-8 decoding so corrupted data becomes an error instead of silently changing dialogue. The track's CodecPrivate contains the ASS script header, including styles and script resolution. Preserve it at track scope; it is configuration, not a cue.

Know when to stop extending regexes

Positioning, layers, script coordinates, karaoke, vector drawings, style inheritance, and attached fonts form a rendering system. For real ASS fidelity, integrate libass or an equivalent maintained renderer rather than growing the plain-text sanitizer forever.

Zoom level 4 · Container boundary

7. Make the demuxer yield complete timed packets

Now the ASS interpreter tells us exactly what it needs:

type SubtitlePacket = {
  data: Uint8Array;  // exactly one embedded ASS event
  startUs: number;
  endUs: number;
};

getSubtitleData(index) belongs beside the audio and video generators. It walks Segment children and Clusters, filters by the selected track's Matroska track number, and yields packets in media order. The caller's subtitle-array index is not the same as the track number stored in a Block.

Start and duration come from different elements

startUs =
  (clusterTimestamp + signedBlockTimestamp) * timestampScaleNs / 1_000;

durationUs = blockDurationTicks * timestampScaleNs / 1_000;
endUs = startUs + durationUs;

BlockDuration is a sibling of Block inside a BlockGroup. Do not throw away the group after finding its Block. When BlockDuration is absent, track-level DefaultDuration is already in nanoseconds, so convert it with / 1_000 and do not apply TimestampScale again.

If neither duration exists, report an unsupported-duration error for this implementation. Do not guess the cue end from the next cue: events can overlap, and the next event may be far away.

Walk the Segment, not an imagined Cluster-only stream

  1. Start at the first Cluster offset.
  2. Inspect each Segment child; skip known-size non-Cluster elements.
  3. Within a Cluster, inspect SimpleBlock and BlockGroup.
  4. Parse enough of the Block header to filter by track before reading its whole payload.
  5. Resolve duration, calculate microsecond times, and yield the event bytes.
  6. End normally only at the Segment boundary or real EOF; malformed input is not EOF.
First-version limits should be loud

If track timestamp scaling, content encodings, unknown-size traversal, or subtitle lacing is not implemented, reject that selected track with a precise error. Silently skipping its packets produces a believable but wrong player.

Zoom level 5 · Block bytes

8. Only now parse the Block header

The EBML element parser has already located the Block payload. At block.dataStart, a second header begins: 

[track VINT][signed relative time: 2 bytes][flags: 1 byte][event bytes…]
83          FF 06                           00            31 32 2C 30…
track 3     -250 ticks                      no lacing     "12,0…"
  1. Decode the track-number VINT and retain its byte width.
  2. Read the next two bytes as a signed big-endian 16-bit integer.
  3. Read flags and extract lacing with (flags & 0x06) >> 1.
  4. The packet region begins after trackWidth + 3 bytes.
const track = await readTrackNumberVint(block.dataStart);
const timeOffset = block.dataStart + track.width;

if (timeOffset + 3 > block.end) throw new Error("Truncated Block header");

const unsigned = await parseNumberAt(timeOffset, 2);
const relativeTimestamp = unsigned >= 0x8000
  ? unsigned - 0x10000
  : unsigned;

const flags = await parseNumberAt(timeOffset + 2, 1);
const lacing = (flags & 0x06) >> 1;
const payloadStart = timeOffset + 3;

Do not hard-code a one-byte track number. Do not use an EBML element-size helper that maps all-one value bits to “unknown size”: track-number VINTs are values, and zero is invalid. Read exactly block.end - payloadStart bytes only after confirming the selected track and supported lacing mode.

Worked timing check

With Cluster Timestamp 10000, relative timestamp −250, TimestampScale 1,000,000 ns, and BlockDuration 1800 ticks: start is 9.75 s, duration is 1.8 s, and end is 11.55 s.

Zoom level 2 · Return to the owner

9. Treat seek and replacement as new sessions

The controller must own stale asynchronous work. Use an AbortController where the backend supports it, plus a monotonically increasing generation for results already in flight: 

async function select(trackIndex: number | null) {
  const generation = ++currentGeneration;
  clearTimelineAndOverlay();
  if (trackIndex === null) return;

  for await (const packet of mkv.getSubtitleData(trackIndex)) {
    if (generation !== currentGeneration) break;
    await waitForReadAheadCapacity();
    if (generation !== currentGeneration) break;
    const cue = packetToCue(packet);
    if (cue) timeline.add(cue);
  }
}

Track off / switch

Invalidate the producer, clear cues and DOM immediately, then start the new track.

Backward seek

Discard the forward-only queue and repopulate from an indexed point before the target.

Forward seek

Drop expired cues and reposition reading; scanning from file start is only a prototype.

Subtitle error

Disable that track and report it without tearing down healthy audio and video.

EOF stops the producer, not the timeline. Buffered final cues remain eligible until their end times. A stopped or replaced generation, by contrast, clears them immediately.

Diagnose a blank overlay in order

  1. Did the selected array index resolve to the intended Matroska track number?
  2. Did the demuxer yield bytes and valid start/end times?
  3. Did field 9 contain renderable text rather than a drawing event?
  4. Are cue times and nowUs on the same microsecond timeline?
  5. Is the cue active at the inspected instant?
  6. Does the overlay contain text but sit behind or outside the visible picture?
Done means behavior, not parsing

Correct dialogue appears and expires with the movie, overlaps survive, the overlay follows resize/fullscreen, subtitle failure leaves playback alive, and old sessions cannot repaint. ASS styling fidelity is a separate milestone.

Work top down to assign responsibilities, verify the deep contracts independently, then return to the screen. If the viewer-visible promise fails, the feature is not finished no matter how convincing the Block parser looks.
