Senmei implementation guide

Build the audio path from the outside in.

Do not begin with PCM vocabulary or EBML bit fields. Begin with the promise the player makes: after Play, the selected MKV audio track is audible, continuous, synchronized, and stoppable. Then assign each part of that promise to one layer.

Scope

This guide follows Senmei's current supported path: Matroska containing AAC-LC, WebCodecs for decoding, and Web Audio for output. It is an implementation map, not an explanation of AAC compression mathematics.

Zoom level 0 · Product behavior

1. First define what “audio works” means

A decoder producing data is not success. The player owns an end-to-end behavior with six observable requirements:

  1. A user action starts or resumes browser audio.
  2. The selected MKV track is the track being heard.
  3. Packets that belong at time t play at movie time t.
  4. Small read and decode delays do not create audible gaps.
  5. End-of-file drains normally; malformed input reports an error.
  6. Stop, seek, and replacement playback cannot leak old audio into the new session.

These requirements tell us what state the design needs: a selected track, a media clock mapping, a scheduling horizon, cancellation, and explicit end/error handling. None of those decisions should be hidden inside the lacing parser.

The central distinction

Media time says where sound belongs in the movie. Wall-clock time says when JavaScript happened to finish decoding it. Never replace the first with the second.

Zoom level 1 · System

2. Draw the whole path before implementing a piece

MKV bytesClusters contain blocks for several tracks.
DemuxerYields one compressed AAC packet with media timing.
AudioDecoderTurns AAC packets into timestamped PCM samples.
Web AudioSchedules those samples against its hardware clock.

Each boundary has one narrow contract:

Container → decoder

Compressed bytes, codec configuration, and a timestamp in microseconds. No speakers, no AudioBuffer, no playback policy.

Decoder → output

AudioData: decoded sample frames plus their rate, channels, format, and media timestamp.

Output → scheduler

Planar float samples and a media timestamp. The scheduler chooses an AudioContext start time.

Player → everything

Play, stop, seek, and error ownership. This is the only layer that knows the whole session.

Key design rule

getAudioData() demuxes. It does not decode or play. The decoder does not decide synchronization. The scheduler does not parse Matroska.

Zoom level 2 · Control flow

3. Write the orchestration as a readable story

The top-level function should reveal the lifecycle even before its helpers exist. In pseudocode, Senmei's audio session is this: 

async function playAudio(mkv, trackIndex, signal) {
  const track = mkv.audios[trackIndex];
  const context = new AudioContext();

  await context.resume();                    // must follow a user gesture
  const scheduler = createScheduler(context);
  const decoder = await createAacDecoder(track, scheduler.push);

  try {
    for await (const packet of mkv.getAudioData(trackIndex)) {
      if (signal.aborted) break;
      await waitForCapacity(decoder, scheduler, signal);
      decoder.decode(toEncodedAudioChunk(packet));
    }

    await decoder.flush();                   // drain submitted packets
    await scheduler.finished();              // optional: wait for audible tail
  } finally {
    scheduler.stop();
    decoder.close();
    await context.close();
  }
}

Read it top to bottom: establish output, create collaborators, feed with backpressure, drain, then release. Details belong behind those names. The structure also exposes two different endings: flush() means decoding is done; it does not mean the last scheduled sound has reached the speakers.

Do not lose asynchronous errors

Throwing inside an AudioDecoder error callback does not reliably reject the loop that called decode(). Store or forward that failure into the session's promise/cancellation path so the owner can clean up and report it.

Zoom level 3 · Demux boundary

4. Make the demuxer yield decoder-ready packets

One yielded item should be sufficient to construct one EncodedAudioChunk. Define that result before walking any Cluster: 

type AudioPacket = {
  data: Uint8Array;       // exactly one raw AAC access unit
  timestamp: number;      // media time, microseconds
  duration: number;       // microseconds
  type: "key";            // required by the WebCodecs AAC registration
};

Codec-wide values do not need to repeat on every packet. The selected track already owns codec, description, sampleRate, channel count, and framesPerPacket. Keep those in track metadata and keep packet output small.

Walk containers in media order

  1. Read a Cluster and its Cluster Timestamp.
  2. Visit each SimpleBlock or BlockGroup/Block in file order.
  3. Parse the track number, signed relative timestamp, flags, and payload layout.
  4. Ignore blocks from other tracks.
  5. Split the selected block into one or more packet ranges.
  6. Yield one AudioPacket for every range.

Convert timestamps once, at the boundary

Matroska block time becomes WebCodecs microseconds:

blockTimeUs =
  (clusterTimestamp + signedBlockTimestamp) * timestampScaleNs / 1_000;

For AAC-LC, one packet produces either 1024 or 960 sample frames according to the parsed AudioSpecificConfig. Its duration is therefore: 

packetDurationUs = framesPerPacket / sampleRate * 1_000_000;
packetTimestampUs(i) = blockTimeUs + i * packetDurationUs;

Derive every packet timestamp from i. Repeatedly adding a rounded duration accumulates drift. Compressed byte length tells you nothing about playback duration.

Demuxer invariant

Concatenating all packet ranges must reproduce the block's frame-data region exactly: no lacing header bytes, overlaps, holes, or bytes past the block end.

Zoom level 3 · Decode boundary

5. Configure once, then feed without assumptions

Senmei's AAC parser already obtains the values the browser needs from CodecPrivate. Validate the exact configuration before opening the session: 

const config = {
  codec: track.codecFormat.codec,                 // e.g. mp4a.40.2
  description: track.codecFormat.description,     // AudioSpecificConfig
  sampleRate: track.codecFormat.sampleRate,
  numberOfChannels: track.codecFormat.numberOfChannels,
};

const support = await AudioDecoder.isConfigSupported(config);
if (!support.supported) throw new Error("AAC configuration is not supported");
decoder.configure(support.config);

With description present, WebCodecs expects raw AAC access units. Do not add ADTS headers. “Raw” here still means compressed AAC; it only means the transport wrapper is absent. 

decoder.decode(new EncodedAudioChunk({
  type: "key",
  data: packet.data,
  timestamp: Math.round(packet.timestamp),
  duration: Math.round(packet.duration),
}));

Output is callback-driven

decode() queues work and returns undefined. The output callback may run later, and code must not assume one immediate output per call. At finite end-of-file, await decoder.flush() waits for all submitted work to emit or fail.

Backpressure has two measurements

decoder.decodeQueueSize limits compressed work waiting in WebCodecs. The scheduler's queued seconds limit decoded sound waiting in Web Audio. Watching only one can still buffer the whole movie or starve playback.

Zoom level 3 · Playback boundary

6. Map media time onto the AudioContext clock

WebCodecs timestamps are media microseconds. Web Audio schedules against AudioContext.currentTime in seconds. Anchor those clocks once: 

mediaOriginUs = firstAudioData.timestamp;
contextOriginS = context.currentTime + startupLeadS;

function contextTimeFor(mediaTimestampUs) {
  return contextOriginS + (mediaTimestampUs - mediaOriginUs) / 1_000_000;
}

If audio and video have a shared player clock, use the same media origin for both instead of independently zeroing each track. Otherwise an intentional track offset disappears.

Copy decoded samples into Web Audio

function schedule(data) {
  try {
    const buffer = context.createBuffer(
      data.numberOfChannels,
      data.numberOfFrames,
      data.sampleRate,
    );

    for (let channel = 0; channel < data.numberOfChannels; channel++) {
      data.copyTo(buffer.getChannelData(channel), {
        planeIndex: channel,
        format: "f32-planar",
      });
    }

    const source = context.createBufferSource();
    source.buffer = buffer;
    source.connect(context.destination);
    source.start(contextTimeFor(data.timestamp));
    remember(source); // stop it if this session is cancelled
  } finally {
    data.close();
  }
}

AudioData owns a media resource, so close it after copying. The AudioBuffer remains valid. Keep the decoded sample rate intact: relabeling 44.1 kHz samples as 48 kHz changes speed and pitch; it is not resampling.

Schedule ahead, within a bounded horizon

JavaScript timers are not an audio clock. Maintain a small lead—enough to absorb ordinary demux and decode jitter—while stopping input when too much sound is already scheduled. Express the limit in seconds, not object count. 

scheduledAheadS = lastScheduledEndS - context.currentTime;

if (scheduledAheadS >= MAX_AUDIO_AHEAD_S) {
  await scheduler.onCapacity(signal);
}
A useful prototype is not full synchronization

Scheduling every output at nextStart += buffer.duration can produce smooth sound, but it erases timestamp gaps and overlaps. It is acceptable as a diagnostic; timestamp-to-clock mapping is the player model.

Zoom level 4 · Container bytes

7. Only now zoom into Matroska lacing

The architecture asks the demuxer for exactly one AAC access unit per yielded packet. Matroska may store several units in one block to save header space. Lacing is simply the rule for recovering their byte ranges. 

block = track VINT | signed timecode | flags | lace header? | frame data
lacingMode = (flags & 0x06) >> 1;
Mode Value How packet sizes are encoded
None 0 All bytes after flags are one packet.
Xiph 1 Runs of 255 plus a terminating byte for each size.
Fixed 2 Frame-data bytes divide equally among all packets.
EBML 3 First size is unsigned; following stored sizes are signed deltas.

For laced modes, the first byte after flags is packetCount - 1. Size metadata exists for every packet except the last, whose size is the remaining frame-data length.

EBML lacing, worked once

82 00 00 86 | 02 | 41 2C | BD | [A: 300] [B: 298] [C: 301]
block header   count  size A   delta       compressed AAC packets
  1. 02 + 1 gives three packets.
  2. 41 2C is an unsigned EBML VINT with value 300.
  3. BD has unsigned VINT value 61. The one-byte signed bias is 63, so the delta is 61 - 63 = -2. Packet B is 298 bytes.
  4. After the lace header, 899 frame-data bytes remain. Packet C receives 899 - 300 - 298 = 301.

For a VINT width of w, the signed bias is 2 ** (7 * w - 1) - 1. Do not reuse the “all ones means unknown element size” rule here: lacing VINTs are values, not EBML element sizes.

Xiph and fixed-size validation

In Xiph lacing, keep adding bytes until a value below 255 ends the size. Thus 300 is FF 2D, and exactly 255 is FF 00. In fixed-size lacing, the frame-data length must divide evenly by packet count. In every mode reject truncated headers, non-positive or overflowing sizes, and ranges beyond the block.

Why this mattered in Senmei

Returning early for lacing !== 0 silently discards valid audio. A player timer cannot recover packets the demuxer never yielded. Parse the layout or fail with a specific unsupported-input error; never skip it as if it were another track.

Zoom level 2 · Return to the owner

8. Finish the lifecycle, not just the happy path

After implementing the deep layers, return to the player contract. The session owns every resource it created and must invalidate asynchronous work when playback changes.

Normal end-of-file

Stop reading, flush the decoder, let the scheduled tail play, then release resources.

Stop or replacement

Abort reads, reset/close decoding, stop remembered source nodes, and close the context.

Seek

Invalidate the old generation before reading the new position; old callbacks must be ignored.

Malformed input

Reject with context such as cluster offset, track number, and lacing mode. Do not call it EOF.

An AbortSignal handles cooperative cancellation. A monotonically increasing session or seek generation handles callbacks already queued before cancellation. Check it in decoder output before scheduling anything.

Zoom level 0 · Observable result

9. Verify from narrow contracts back to the player

Debug in the same layered order as the architecture, not by changing random timers.

  1. Demux: log packet count, byte length, timestamp, and duration. Assert timestamps are monotonic and laced ranges exactly consume frame data.
  2. Decode: verify isConfigSupported(), then log output timestamp, frames, rate, and channels. Confirm outputs are closed after copying.
  3. Schedule: log media timestamp, chosen context start, and scheduled-ahead seconds. Confirm starts are future times during steady playback.
  4. Listen: use a file with dialogue or sharp transients. Check startup, several uninterrupted minutes, stop, replay, and seek.
  5. Synchronize: compare a visible impact or mouth movement against sound. Smooth but shifted audio is still wrong.
Reading symptoms

Silence with no decoded output points upward toward demux/configuration. Decoded output with silence points downward toward context state, copying, connection, or scheduling. Chopping points to scheduling lead or starvation. Smooth drift points to timestamp math, sample rate, or clock mapping.

The implementation is done when the original product behavior holds—not when a byte parser passes in isolation. Work top down to decide responsibilities, bottom up to verify each contract, then return to the player and listen.
